# Report interpretation hotfix — 2026-10-26

## Scope and behavior

Source commit: `b45a9f0f0cce3151708efc4b5277ff3fa7b3d979`.
Deployed to the RCON3/4 backends and supervisors and the shared Discord service.
The public version remains `v0.9.3-rc.1`; no release tag or registry image was
replaced. No schema migration or historical report replay was performed.

- The model prompt treats `NO MIC` and equivalent complaints as communication
  complaints, without inventing an unsupported hardware-versus-behavior distinction.
- A spelling note about a reported name is separate from a blocking uncertainty
  about the allegation. Independent roster, identity and role checks still apply.
- Complaints about Nazi slogans, insults, discriminatory content or threats are
  routed for manual review. A rejection-only backend guard prevents such wording
  from authorizing a communication kick even if the model misclassifies it.
- Manual decisions, ambiguous or ungrounded interpretations, category conflicts,
  and squad-less reporter/target conditions have separate diagnostic reasons.
  Existing identity and eligibility safeguards were not relaxed.
- Prompt `report-reason-6` uses an internal spelling-note field and strips it
  before returning the unchanged wire contract to other installations.

## Follow-up: provider schema rejection — 2026-10-27

The first six natural RCON3 reports after the October 26 deployment all reached
Discord but failed AI interpretation. The central service returned HTTP 503 with
`codex_turn_failed`; the latest examples were the Jolly-Etico reports at 17:16 and
17:22 UTC on October 27. There were no recent RCON4 reports in the inspected window.

An interpretation-only probe with fictional players captured the provider's
HTTP 400 `invalid_json_schema`: `name_spelling_note` was absent from `required`.
Its Pydantic default had made the new property optional. Codex forwards this raw
schema, while Structured Outputs requires every declared property to be required
([official documentation](https://developers.openai.com/api/docs/guides/structured-outputs)).
The previous mocked tests checked the property's existence and wire compatibility
but missed this provider constraint. The initial deployment health checks had
not exercised a real model invocation.

Correction `4c565a34d1109d5d46edc37ee5062198721f6f31` removes the default, requires
an empty string when no spelling note applies, and advances the interpretation
version to `report-reason-7`. The shared response contract and moderation rules
remain unchanged. A new regression demonstrably failed on the old source and
passed with the fix; all **130 Discord-service tests passed**.

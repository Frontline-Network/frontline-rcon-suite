# Report interpretation hotfix — 2026-10-26

## Scope and behavior

Source commit: `b45a9f0f0cce3151708efc4b5277ff3fa7b3d979`.
Deployed to the RCON3/4 backends and supervisors and the shared Discord service.
The public version remains `v0.9.3-rc.1`; no release tag or registry image was
replaced. No schema migration or historical report replay was performed.

- The model prompt treats `NO MIC` and equivalent complaints as communication
  complaints, without inventing an unsupported hardware-versus-behavior distinction.
- A spelling note about a reported name is separate from a blocking uncertainty
  about the allegation. Independent roster, identity and role checks still apply.
- Complaints about Nazi slogans, insults, discriminatory content or threats are
  routed for manual review. A rejection-only backend guard prevents such wording
  from authorizing a communication kick even if the model misclassifies it.
- Manual decisions, ambiguous or ungrounded interpretations, category conflicts,
  and squad-less reporter/target conditions have separate diagnostic reasons.
  Existing identity and eligibility safeguards were not relaxed.
- Prompt `report-reason-6` uses an internal spelling-note field and strips it
  before returning the unchanged wire contract to other installations.

## Validation

480 local tests passed: 351 backend report tests and 129 Discord-service tests.
Formatting and diff whitespace checks passed. Model and game actions were mocked.
Both built images then passed isolated regression checks with no network access,
no production mounts and no model calls or player actions. Exact deployed source
hashes match the committed patch, and original image layers are preserved.

The first isolated check could not write its startup log on a read-only filesystem.
The check was corrected to use an ephemeral `/tmp` log directory and passed before
any production container was replaced. No production configuration change was
needed for this test-environment issue.

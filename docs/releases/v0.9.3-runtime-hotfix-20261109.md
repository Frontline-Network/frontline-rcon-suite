# Runtime hotfix after v0.9.3 — RCON3/4

## Changes

- Read complete TCP headers and bodies across fragmented reads, send complete
  requests, and stop immediately on EOF. Bound response sizes and deadlines so
  a closed or trickling connection cannot occupy a worker indefinitely.
- Close failed handshakes and invalid response streams. Replace closed pooled
  connections before retrying and preserve the transport error classification.
  Authentication failures and the existing no-retry scope remain unchanged.
- Run log rotation from any active supervisor rather than only server 1. Keep
  the lock and rotation state on the shared log volume so concurrent cron jobs
  and container restarts are safe. Configuration/locking errors remain visible.
- Operational change authorized by the owner: clear only RCON3's obsolete
  `AutoModSeedingUserConfig.discord_webhook_url`. The deleted Discord endpoint
  caused the audit-webhook failures; generic audit-webhook settings were empty.
  Seeding enforcement and normal Discord reports remain enabled as configured.

## Validation

113 isolated Linux tests passed: framing, connection cleanup, no-retry kick
guards, transport classification, HLL/HLLV game profiles and actual logrotate
execution with concurrent-lock and persistent-state checks. The test environment
used a disposable empty Redis container without external networking. Pytest's
capture handler was attached to the production logger, which disables propagation.
One existing dependency warning concerns Python's deprecated `audioop` module.

No schema, UI, game rules, permissions or SMTP changes are required. The runtime
fix reduces recoverable transport failures; it cannot prevent outages or invalid
responses originating in the game server itself.

## Rollout and recovery

Scope: RCON3 and RCON4 on the existing RCON host. Preserve retired RCON1/2 and
all other tenants. Use an immutable derivative of the running v0.9.3 backend
image, keep frontends unchanged, and verify RCON4 before RCON3.

Private backup directory:
`/root/hll_rcon_tool/.deploy-state/hotfix-runtime-20261109`.

Before rollout, the PostgreSQL dump was fully read with `pg_restore`, Redis was
checked with `redis-check-rdb`, and configuration/rollback Compose files were
saved. All 171 existing log files were also archived and read back before the
first rotation (6,871,040,199 uncompressed bytes).

The original Seeding webhook configuration is retained privately in
`seeding-webhook-before.json`; do not automatically restore a known deleted URL.
Rollback uses `compose.rollback.json` for the affected backend/supervisor
services and the original rotation script from the configuration archive.
Database and Redis restores are unnecessary for this code-only rollback and
would overwrite newer live data.

Post-deployment evidence belongs in the accompanying rollout receipt: image and
source hashes, live read-only RCON calls, supervisor states, API freshness, SMTP,
normal report delivery, rotation state, protected containers and database grants.

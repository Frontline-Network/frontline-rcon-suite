# v0.9.3: Live-Protokoll und Theme-Ladefehler

Das Live-Protokoll überträgt beim regelmäßigen Abruf nur neue Ereignisse.
Ältere Meldungen lassen sich getrennt laden; Scrollen in der festen Protokoll-
Ansicht und Blättern pausieren die Aktualisierung. „Live fortsetzen“ kehrt zum
Anfang zurück. Das gespeicherte Abruflimit begrenzt das geladene Fenster; pro
Anfrage kommen höchstens 500 Rohereignisse. Filter bleiben erhalten. Enthält
eine Rohseite keine passenden Treffer, kann trotzdem weitergeblättert werden.

Die bestehende API erhält einen optionalen Cursor-Modus. Alte Clients verwenden
weiterhin das bisherige Verhalten und dieselbe Berechtigung. Die Ereignis-ID
basiert auf der Identität des Log-Recorders, damit Meldungen mit demselben
Zeitstempel nicht verloren gehen. Überlappende Redis-Seiten werden dedupliziert.
Nach Ablauf eines Cursors oder mehr als einer Seite neuer Ereignisse wird das
aktuelle Fenster sichtbar zurückgesetzt; es wird keine lückenlose Historie
vorgegeben. Die vollständige gespeicherte Historie bleibt unter Spielprotokolle.

Ein fehlgeschlagenes Nachladen des Themes erzeugt eine verständliche deutsche
oder englische Fehlermeldung mit Neuladen-Schaltfläche statt einer leeren Seite.
Es gibt höchstens einen automatischen Wiederholungsversuch, keine Reload-Schleife.
Der globale Query-Cache verwendet die gültige v5-Option `gcTime`. Inaktive
Live-Protokollabfragen werden bereits nach einer Minute freigegeben.

## Validierung und Rollout

16 isolierte Backendtests für Cursor, Filter, gleiche Zeitstempel, überlappende
Seiten, leere Antworten und abgelaufene Fenster. Frontend-Tests prüfen Merging,
Speichergrenze, Theme-Fehler und Wiederholung. Browserprüfungen decken Cursor-
Polling, Pause/Fortsetzen, ältere Seiten, Filterwechsel, gespeicherte Einstellungen,
100er-Nachrichtenstapel und mobile Bedienung ab. Der Produktionsbuild und die
Prüfungen für Übersetzungen, CSRF, Polling und anfängliche Paketgröße gehören
zur Abnahme.

Pilot ausschließlich auf RCON4, danach RCON3. Die bestehenden Backend- und
Frontend-Images bilden die Basis; keine Datenmigration. Alte Frontend-Assets
bleiben für bereits geöffnete Tabs erreichbar. Angezeigte Version bleibt v0.9.3.
Keine Änderung an Spielregeln, Discord-Konfiguration, SMTP oder anderen Instanzen.

Geprüfte Sicherung und unveränderliche Rücksprung-Images:
`/root/hll_rcon_tool/.deploy-state/hotfix-live-ui-20261109`.
PostgreSQL wurde vollständig mit `pg_restore` gelesen, Redis mit
`redis-check-rdb` geprüft; Konfiguration und ursprüngliches Compose sind gesichert.
Rollback betrifft nur Backend und Frontend der jeweiligen Instanz. Dafür keine
Datenbank zurückspielen und keine inzwischen entstandenen Live-Daten überschreiben.

Der [Aufbewahrungsvorschlag](../operations/rcon34-retention-proposal-20261109.md)
ist eine Entscheidungsgrundlage; historische Daten wurden nicht gelöscht.

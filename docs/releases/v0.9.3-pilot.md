- [ ] Full Linux CI with isolated PostgreSQL/Redis, both frontends and Discord.
- [ ] Exact candidate production frontend/backend version and authenticated smoke.
- [ ] Image contents and release notes match the reviewed candidate; immutable
      image references are recorded, without moving stable `latest`.

      references backed up privately; database restoration checked in isolation.
- [ ] Upgrade rehearsal preserves configuration, direct/group grants and user
      preferences. Old votes cannot resume; existing automations retain their mode.
- [ ] Derive Compose from each actual service, preserving SMTP and private origins.
      Do not restart shared databases, Redis, game servers or unrelated services.
- [ ] Verify source, collected and public admin JS/CSS hashes, especially API-key
      generation and all permission-wizard assets. Stale files fail deployment.
- [ ] Test limited-role read-only access, combined groups and API-key generation
      without granting superuser as a workaround or exposing key values.
- [ ] Rollback plan accounts for compatible schema; never blindly downgrade or
      restore the live database over new data.

## Pilot observation

Check fresh live/map data, round boundaries, persisted player statistics, Discord
delivery/actions, report-admin decisions and reporter receipts, error rates,
service health and resource use. Installation alone is not behavioral proof.

Use synthetic isolated tests for deliberate sanctions. No unsolicited test
messages, reports, kicks or team moves. Normal configured live moderation remains
possible. Self-report testing is an existing explicit exception on RCON3/4; do not
silently enable it elsewhere or change it as part of this rollout.

The new member and teamkill execution paths need particular observation. Cheating
continues to require human action. HLL-specific seeding and map behavior cannot
be fully accepted solely on the HLLV pilot; keep HLL automated regression checks
and obtain separate approval for any later HLL pilot.

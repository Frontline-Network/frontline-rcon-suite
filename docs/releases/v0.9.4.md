# Frontline RCON Suite v0.9.4

## Deutsch

### VIP-Belohnungen für eure Community

- Neue, serverbezogene VIP-Belohnungen für Rundentreue, regelmäßige Aktivität,
  Spielzeit-Meilensteine, freiwilligen Teamausgleich, Nahkampf, Events und
  Waffen-Challenges. Seed-VIP bleibt separat einstellbar.
- Wöchentliche Unterstützungspunkte als gemeinsames Langzeitziel: Zielpunktzahl,
  VIP-Dauer und Statusbefehl sind einstellbar. Gezählt werden neu beobachtete
  Punkte; daraus werden keine einzelnen gebauten Garnisonen oder Nodes abgeleitet.
- Geführtes Formular mit „Voraussetzungen“ und „Belohnung“, Regelauswahl,
  Schiebereglern, Waffenliste, Spielersuche und auswählbarer Zeitzone. Details
  erscheinen erst nach Aktivierung der jeweiligen Regel. Deutsch und Englisch
  werden unterstützt, auch auf kleinen Bildschirmen.
- Gemeinsames Zeitbudget, Vergabegrenzen pro Tag/Woche/Monat, Spieler-Ausschlüsse
  und eine Seeding-Pause schützen vor unerwünschten Vergaben. Das Journal zeigt
  Vorschauen, tatsächliche Vergaben und Fälle, die geprüft werden müssen.
- Standardmäßig ausgeschaltet und im Probelauf: Vorschau vergibt kein VIP und
  sendet keine Spielernachrichten. Livebetrieb muss bewusst aktiviert werden.
  Der bestehende Autobalancer-Befehl, normalerweise `!balance`, wird mitgenutzt.

### Kampagnen und Live-Protokoll

- Broadcast-Kampagnen zeigen nun ihre eigene Versandaktivität. Ein leerer
  Direktnachrichten-Zähler wird nicht mehr als Nachweis fehlender Broadcasts
  missverstanden. Die Gameserver-Bestätigung beweist keine Anzeige beim Spieler.
- Intervalle lassen sich in Sekunden einstellen. Änderungen werden beim nächsten
  Prüflauf berücksichtigt; Broadcasts verwenden ihre eigene Ablaufsteuerung.
- Live-Logs laden neue Einträge inkrementell. Filter, ältere Einträge sowie
  Pause/Fortsetzen funktionieren wieder zuverlässig.

### Zuverlässigkeit und kleineres Update-Paket

- Vorübergehende Kontextlücken brechen die KI-Report-Bearbeitung nicht mehr
  vorschnell ab. Sitzungsereignisse und Spielzeiten werden robuster verarbeitet.
- RCON-Verbindungen behandeln unvollständige Antworten und Verbindungsabbrüche
  robuster. Unklare Spielermaßnahmen werden nicht blind wiederholt.
- Gemeinsame Logrotation funktioniert auch bei abgeschalteten Instanzen.
  Datenbankmigrationen werden beim Start geprüft, nicht neu erzeugt.
- Das Backend-Paket enthält nur benötigte Laufzeitdateien. Der bisherige
  kontrollierte Vergleich ergab rund 42 % weniger entpackte Größe; zusätzliche
  Funktionen verändern die endgültige Release-Größe. Dies ist kein RAM- oder
  Geschwindigkeitstest.
- Produktions-Builds normalisieren die API-Adresse und stellen lesbare
  Frontend-Dateien sicher; damit werden die beobachteten leeren Seiten vermieden.

### Aktualisierung

Backend und Frontend gemeinsam aktualisieren und vorher Datenbank, Redis sowie
Konfiguration sichern. Neue VIP-Tabellen werden durch Migrationen angelegt.
Bestehende Einstellungen, Rechte, API-Schlüssel, SMTP und Spielerdaten bleiben
erhalten. Keine automatischen Löschungen oder nachträglichen VIP-Vergaben.
Die eigenen Neuigkeiten zu v0.9.4 erscheinen einmal je Benutzerkonto; frühere
Ankündigungen werden dadurch nicht erneut abgespielt.

## English

### VIP rewards for your community

- New per-server VIP rewards for round loyalty, regular activity, playtime
  milestones, voluntary balancing, melee, events and weapon challenges.
  Seed-VIP retains its separate settings.
- Weekly support points provide a longer-term goal with configurable target,
  VIP duration and progress command. Only newly observed points count; they
  do not identify individual garrisons or nodes built.
- A guided form separates requirements and rewards, with a rule navigator,
  sliders, weapon selection, player search and time zones. Details appear when
  a rule is enabled. German, English and smaller screens are supported.
- Shared time budgets, daily/weekly/monthly award limits, player exclusions
  and a seeding pause control awards. The journal distinguishes previews,
  confirmed awards and cases requiring review.
- Disabled by default with preview mode selected. Preview grants no VIP and
  sends no player messages. Live operation requires deliberate activation.
  Volunteers use the existing autobalancer command, normally `!balance`.

### Campaigns and live logs

- Broadcast campaigns show their own delivery activity, separate from direct
  messages. Gameserver acknowledgement does not prove a player saw the message.
- Intervals can be set in seconds. Changes apply on the next processing cycle;
  broadcasts use their own scheduling state.
- Live logs load new entries incrementally, with reliable filtering, older
  entries and pause/resume controls.

### Reliability and smaller updates

- Temporary context gaps no longer prematurely abandon AI report processing.
  Session events and playtime are handled more robustly.
- RCON connections handle partial replies and disconnections more reliably.
  Uncertain player actions are not blindly repeated.
- Shared log rotation supports disabled instances. Startup checks database
  migrations instead of generating them.
- Backend packages contain required runtime files only. The earlier controlled
  comparison showed about 42% smaller unpacked size; added features affect the
  final release size. This is not a RAM or response-time benchmark.
- Production builds normalize the API URL and preserve readable frontend assets,
  addressing the observed blank-page failures.

### Upgrading

Update backend and frontend together after backing up the database, Redis and
configuration. Migrations add VIP reward tables. Existing settings, permissions,
API keys, SMTP and player data are preserved. No automatic deletion or retroactive
VIP grants. The new v0.9.4 announcement appears once per account, without replaying
older announcements.

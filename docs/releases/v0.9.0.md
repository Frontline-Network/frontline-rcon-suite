# Frontline RCON Suite v0.9.0

## Deutsch

### Dein RCON, dein Arbeitsbereich

- **Aurora und Vanguard:** Das zusätzliche Theme heißt Aurora, das bisherige Theme Vanguard. Bestehende Darstellungspräferenzen bleiben erhalten. Aurora bietet sechs Farbstile mit passenden **statischen Hintergrundbildern**; die zwischenzeitlichen Funkenanimationen sind nicht Teil dieses Releases.
- **Operative Übersicht:** Überarbeitete Anordnung und Darstellung der Betriebsinformationen, klarere Statusbereiche und Navigation. Aurora-Schnellzugriffe lassen sich im eigenen Konto konfigurieren.
- **Administration und Hilfe im RCON:** Benutzer- und Berechtigungsverwaltung, Bedienhilfe und API-Dokumentation sind in die Oberfläche eingebettet. Auch Vanguard integriert die Administration optisch. Bestehende Zugriffsrechte gelten weiterhin.
- **Spielerprofile und Sidecard:** Überarbeitete, kompaktere Darstellung von Identität, Status und Spielerinformationen. Kryptische Plattformangaben wie `EPlatformFamily::Steam` werden durch lesbare Namen ersetzt. Plattform-IDs stehen getrennt von der EOS-ID bereit, sofern der Gameserver sie liefert. Steam-IDs verlinken auf Steamprofile; Konsolenprofile werden nur bei geeigneter, verlässlich zuordenbarer Kennung verlinkt.

### Konto und Updates

- Das eigene Passwort lässt sich innerhalb der Oberfläche ändern. Optional ist eine Wiederherstellung per E-Mail möglich; sie benötigt eine eingerichtete Mail-Konfiguration und eine gültige E-Mail-Adresse am Konto.
- Der private Update-Kanal zeigt nur zur **installierten Version** passende Veröffentlichungen und deren ältere Historie. Unterschiedliche Frontend-/Backend-Versionen kündigen keine neuere Version an. Browser benötigen keinen GitHub-Zugang.
- Kurze Release-Highlights sind auf Deutsch und Englisch verfügbar. Sie erscheinen einmal pro Konto und Version auf der freien Übersicht, nicht während Eingaben oder anderer Dialoge. Der Status gilt auch in anderen Sitzungen/Geräten. „Später“ verschiebt die Erinnerung um 24 Stunden; „Was ist neu?“ öffnet sie manuell erneut.
- Zurückgestellte automatische Einblendungen werden nach Ende einer Eingabe oder eines Dialogs wieder geprüft. Theme-Bestandteile und Moderationsdialoge werden bedarfsgerecht geladen; die bestehenden JavaScript-Budgets bleiben unverändert.

### Führungsabstimmungen

- Geeignete Reports können die Führungsabstimmung direkt mit Einladungen an die berechtigten Führungskräfte starten. Dieser Stand (`ffd4deb5`) war ausdrücklich **nicht in v0.8.8** enthalten und ist jetzt dabei.
- Auch normale Squadmitglieder dürfen Führungskräfte melden. Stimmrechte bleiben auf die berechtigten Führungskräfte beschränkt; ein normales Squadmitglied erhält durch seinen Report keine Stimme. Berechtigte Führungskräfte dürfen weiterhin mitstimmen.
- Ziel-, Team-, Rollen-, Mehrheits- und Ausführungsschutz bleiben erhalten. Dieses Release schaltet keine Serverfunktion oder echten Kicks eigenständig ein und ändert keine produktive Serverkonfiguration.

### Hinweise für Administratoren

1. Vor einem späteren Rollout Datenbank und Konfiguration sichern. Backend und Frontend gemeinsam auf **v0.9.0** aktualisieren; dieses Release führt noch keinen Server-Rollout aus.
2. Die regulären Datenbankmigrationen ausführen. Django-Migration **0040** speichert den kontobezogenen Highlight-Status. **0041** gleicht den Standardwert der Darstellungspräferenzen mit dem Modell ab; bestehende Einstellungen werden nicht überschrieben. Der vorhandene BigAutoField-Primärschlüssel bleibt erhalten.
3. Passwortwiederherstellung bleibt standardmäßig aus. Erst nach Einrichtung von `CRCON_PUBLIC_URL` (öffentliche HTTPS-Adresse), `EMAIL_HOST`, `EMAIL_PORT`, `EMAIL_HOST_USER`, `EMAIL_HOST_PASSWORD`, `DEFAULT_FROM_EMAIL` und passendem TLS **oder** SSL `CRCON_PASSWORD_RESET_ENABLED` aktivieren. Mailzustellung prüfen; Zugangsdaten ausschließlich serverseitig hinterlegen. Reset-Links gelten 30 Minuten.
4. Die veröffentlichten Release Notes einschließlich DE/EN-Highlights werden im Backend-Image gebündelt. Für diese Anzeige ist kein zusätzlicher Laufzeit-GitHub-Token erforderlich. Bei unvollständigem Versionsabgleich bleibt die Ankündigung gesperrt.
5. Ein expliziter Release-Merge mit `#release-manual` behält die Quality Gates, unterdrückt aber den automatischen Patch-Tag. Die Freigabe von v0.9.0 erfolgt ausdrücklich mit veröffentlichten Notes vor dem finalen Image-Sync.

## English

### Your RCON, your workspace

- **Aurora and Vanguard:** The additional theme is named Aurora; the original theme is now Vanguard. Existing appearance preferences are retained. Aurora includes six colour styles with matching **static backgrounds**. The interim spark animations are not included in this release.
- **Operations overview:** Refined arrangement and presentation of operational information, clearer status areas and navigation. Aurora shortcuts can be configured for your own account.
- **Integrated administration and help:** User and permission management, operator help and API documentation are embedded in the interface. Administration also follows the Vanguard appearance. Existing access permissions still apply.
- **Player profiles and sidecard:** A more compact presentation of identity, status and player details. Cryptic platform values such as `EPlatformFamily::Steam` are replaced with readable names. Platform IDs are shown separately from EOS IDs when provided by the game server. Steam IDs link to Steam profiles; console profile links require a suitable, reliably attributable identifier.

### Accounts and updates

- Change your own password within the interface. Optional email-based password recovery requires configured mail delivery and a valid email address on the account.
- The private update channel only displays the **installed version** and its older release history. Mismatched frontend/backend versions do not announce a newer release. Browsers do not need GitHub credentials.
- Curated highlights are available in German and English. They appear once per account and version on an idle overview, without interrupting input or other dialogs. State is shared across sessions/devices. “Later” postpones the reminder for 24 hours; “What’s new?” reopens it manually.
- Deferred automatic highlights are checked again after input or another dialog ends. Theme components and moderation dialogs load on demand; existing JavaScript budgets remain unchanged.

### Leadership votes

- Eligible reports can start leadership votes directly, inviting eligible leaders. This change (`ffd4deb5`) was explicitly **excluded from v0.8.8** and is included now.
- Regular squad members may report leaders. Voting rights remain restricted to eligible leaders; submitting a report does not grant a regular member a ballot. Eligible leaders may still vote.
- Target, team, role, majority and execution safeguards remain in place. This release does not independently enable server features or real kicks, and does not change production server configuration.

### Administrator notes

1. Back up the database and configuration before a subsequent rollout. Update backend and frontend together to **v0.9.0**. Publishing this release does not deploy it to game-server installations.
2. Run the normal database migrations. Django migration **0040** stores account-bound highlight state. **0041** aligns the appearance preference default with the model without overwriting existing settings. The existing BigAutoField primary key is retained.
3. Password recovery is disabled by default. Configure `CRCON_PUBLIC_URL` (public HTTPS origin), `EMAIL_HOST`, `EMAIL_PORT`, `EMAIL_HOST_USER`, `EMAIL_HOST_PASSWORD`, `DEFAULT_FROM_EMAIL` and the appropriate TLS **or** SSL mode before enabling `CRCON_PASSWORD_RESET_ENABLED`. Verify email delivery and keep credentials server-side only. Reset links expire after 30 minutes.
4. Published release notes, including the German/English highlights, are bundled in the backend image. No additional runtime GitHub token is required for this display. Announcements remain disabled until installed versions match.
5. An explicit release merge containing `#release-manual` retains quality gates but suppresses automatic patch tagging. v0.9.0 is published explicitly, with its release body available before the final image snapshot sync.

# Frontline RCON Suite v0.9.4-rc.1

## Deutsch

Release-Kandidat für den Pilotbetrieb auf RCON4 und anschließend RCON3.
Er bündelt die Verbesserungen seit v0.9.3. Der stabile Update-Kanal bleibt
auf v0.9.3; andere Installationen werden nicht automatisch aktualisiert.

### Live-Protokoll und Oberfläche

- Neue Protokolleinträge werden inkrementell geladen. Filter, ältere Einträge
  und Pausieren/Fortsetzen sind wieder zuverlässig nutzbar.
- Die bisherige GET-Schnittstelle bleibt mit optionalen Log-Cursorn kompatibel.
- Fehler bei der Theme-Auswahl lassen sich wieder abfangen; veraltete
  zwischengespeicherte Antworten werden gezielter vermieden.

### Verbindungen und Betrieb

- RCON-Verbindungen verarbeiten unvollständig eintreffende Antworten robuster
  und räumen fehlgeschlagene Verbindungen auf. Wiederholungsversuche sind begrenzt;
  Spielermaßnahmen werden bei unklarem Ergebnis nicht blind wiederholt.
- Die gemeinsame Logrotation funktioniert auch bei abgeschaltetem RCON1.
  Eine gemeinsame Sperre verhindert parallele Rotation mehrerer Instanzen.
- Der Start prüft vorhandene Datenbankmigrationen, statt ungeprüft neue zu
  erzeugen. Veraltete Wartungsmarkierungen werden bereinigt, vertrauliche
  Startparameter nicht mehr durch Shell-Tracing ausgegeben.

### Kleineres Paket, geprüfte Updates

- Das Backend-Image enthält nur benötigte Laufzeitdateien. Im kontrollierten
  Vergleich mit identischer Python-Basis und denselben 95 Python-Paketen sank
  die entpackte Größe von rund 487 auf 284 MiB, also um etwa 42 Prozent.
  Die endgültige Release-Größe kann davon abweichen.
- Ein isolierter Update-Test prüft v0.9.3 → Kandidat, erneutes Anwenden und
  Rückkehr zum alten Anwendungscode. Einstellungen, Rechte, API-Schlüssel,
  Anzeigepräferenzen und Datenbestände werden dabei auf Erhalt geprüft.
- HLL und HLLV sowie getrennter und gemeinsamer API-Betrieb werden geprüft;
  ein zusätzlicher Durchlauf deckt ARM64 ab. Ein Test mit wiederhergestellter
  Produktionssicherung gehört zur Pilot-Ausrollung.

### Hinweise zum Update

- Backend und Frontend gemeinsam aktualisieren. Datenbank, Redis und aktive
  Konfiguration vorher sichern und die Wiederherstellung prüfen.
- Keine neuen Datenbankmigrationen gegenüber v0.9.3. Vorhandene Konfiguration,
  SMTP-Einstellungen und Moderationsregeln bleiben erhalten.
- Dieses Release löscht keine historischen Logs, Backups oder Kundendaten und
  aktiviert keine automatische Datenaufbewahrung. Bisherige manuelle
  Serverbereinigungen werden beim Kundenupdate nicht wiederholt.
- Noch ungelesene Feature-Hinweise aus v0.9.0 bleiben verfügbar. Die geringere
  Image-Größe belegt keine Verringerung des RAM-Bedarfs oder der Antwortzeiten.

## English

Release candidate for a pilot on RCON4, followed by RCON3. It includes the
improvements since v0.9.3. The stable update channel stays on v0.9.3;
other installations are not updated automatically.

### Live logs and interface

- New log entries load incrementally. Filters, older entries and pause/resume
  work reliably again.
- The existing GET interface remains compatible with optional log cursors.
- Theme selection recovers from failures, with more targeted prevention of
  stale cached responses.

### Connections and operations

- RCON connections handle fragmented responses more robustly and clean up
  failed connections. Retries are bounded; player actions are not blindly
  repeated when the outcome is uncertain.
- Shared log rotation works when RCON1 is shut down. A shared lock prevents
  concurrent rotation by multiple instances.
- Startup checks existing database migrations instead of generating new ones.
  Stale maintenance markers are cleared, and shell tracing no longer prints
  confidential startup parameters.

### Smaller package and upgrade checks

- The backend image contains the required runtime files. In a controlled
  comparison using the same Python base and all 95 Python packages, unpacked
  size fell from approximately 487 to 284 MiB, about 42 percent. Final release
  image size may differ.
- Isolated tests cover v0.9.3 → candidate, repeated application and rollback
  to the previous application code. They verify preservation of configuration,
  permissions, API keys, display preferences and stored data.
- Checks cover HLL, HLLV, split and unified API modes, with an additional ARM64
  run. Restoring a production backup is part of the pilot deployment checks.

### Upgrade notes

- Update backend and frontend together. Back up the database, Redis and active
  configuration first and verify recovery.
- No new database migrations compared with v0.9.3. Preserve existing settings,
  SMTP configuration and moderation rules.
- This release does not delete historical logs, backups or customer data, or
  enable automatic retention. Previous manual server cleanups are not repeated
  during customer upgrades.
- Unread v0.9.0 feature announcements remain available. Smaller images do not
  establish lower RAM consumption or faster response times.

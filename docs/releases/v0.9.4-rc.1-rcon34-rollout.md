## Ordered deployment and preservation

RCON4 was updated first. Its public assets, log pagination/filtering, personal
display API, CSRF/authentication boundaries, runtime logs, statistics API,
Discord diagnostics and AI availability passed before RCON3 was updated.
RCON3 then passed the same relevant checks. Only afterward were the RCON
project's background worker and webhook service updated.

Each restart was guarded against open leadership procedures, pending automatic
report actions and an active/armed balance procedure. The temporary balance
execution leases were released. No application rollback was required.

The deployment retained all user configuration, direct/group permissions,
moderation policies, frontend preferences and SMTP configuration. SMTP checks
confirmed the established host, port, account, TLS and configured password,
without sending email or recording credentials in this document.

The central Discord service's 13 Python files already match this release; it was
not restarted. PostgreSQL, Redis, maintenance, retired RCON1/2 and unrelated
installations retained their container identities. Game servers were not
restarted. Optional log-stream, seed-VIP and kill-rate processes returned to
their prior normal EXITED state; all previously running processes remained
RUNNING. All eight updated containers had zero unexpected Docker restarts.

`OPERATIONS.md` in the private directory names the pinned active and rollback
Compose models. Application rollback uses only explicit affected service names
and preserved images/static files. Restoring a database is a separate operation
because it would discard newer live data; it is never automatic.

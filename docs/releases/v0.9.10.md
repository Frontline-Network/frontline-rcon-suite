# Frontline RCON Suite v0.9.10

## Deutsch

Dieses Update macht die RCON-Laufzeit deutlich schlanker, ohne Funktionen,
Einstellungen oder historische Daten zu entfernen.

### Weniger RAM und Prozesse

- Alle 18 Hintergrunddienste bleiben einzeln sichtbar und steuerbar, teilen
  sich aber eine überwachte Python-Runtime. Eigene Prozesse bleiben nur für
  die gemeinsame Runtime, RQ und Cron bestehen.
- Standardinstallationen mit einem API-Worker verwenden einen Daphne-Prozess
  für HTTP und WebSockets. Bewusst konfigurierte Mehrfach-Worker behalten
  automatisch die bisherige geteilte Hochlast-Topologie.
- Daphne, Supervisord und Nginx laufen direkt als Container-Hauptprozess.
  Unnötige Einstiegsshells entfallen und Stop-/Neustarts werden zuverlässiger.

### Gemessene Wirkung

- RCON3 (HLLV): etwa 1.099 MiB auf 562 MiB unter realem Spielbetrieb, rund
  49 % weniger. Spätere Lastmessungen lagen erwartungsgemäß etwas höher.
- HLL1 (HLL): etwa 1.422 MiB auf 405 MiB für die vergleichbaren Kerncontainer,
  rund 72 % weniger. Einschließlich des unveränderten Hintergrund-Workers sind
  es etwa 1.572 MiB auf 555 MiB, rund 65 % weniger.
- Die Messungen vergleichen jeweils denselben Containerumfang; kurzfristige
  Schwankungen durch RQ-Aufträge und aktive Spieler sind weiterhin normal.
- Beide Canaries liefen mit 18/18 Diensten, ohne Container-Neustarts oder neue
  relevante Fehlermarker. Im Leerlauf laufen sieben dauerhafte Kernprozesse;
  während eines RQ-Auftrags vorübergehend acht.

### Update- und Rollback-Sicherheit

- Bestehende Standardinstallationen wechseln automatisch auf die schlanke
  Runtime. Eigene Supervisor-Pfade und Mehrfach-API-Worker werden respektiert.
- `FRONTLINE_SUPERVISOR_RUNTIME_MODE=split` und
  `HLL_API_SERVER_MODE=split` stellen die kompatible frühere Topologie ohne
  Datenmigration wieder her.
- Das Update löscht keine Daten und enthält für diese Umstellung keine neue
  Datenbankmigration. Datenbank, Redis und Konfiguration trotzdem wie gewohnt
  vor dem Update sichern.
- Upgrade-Proben waren für HLL und HLLV, Split und Unified sowie HLLV auf ARM
  erfolgreich. Releases v0.9.0 bis v0.9.5 wurden als Ausgangsstände geprüft.
- Gehostete Neuinstallationen und erneute Bereitstellungen benötigen das
  Frontline-Game-Hosting-Plugin ab v0.17.5, damit dieselben sicheren
  Versionsgrenzen und Runtime-Vorgaben erzeugt werden.

## English

This update makes the RCON runtime substantially lighter without removing
features, settings, or historical data.

### Less memory and fewer processes

- All 18 background services remain individually visible and controllable,
  while sharing one monitored Python runtime. Only the shared runtime, RQ and
  Cron keep dedicated Supervisor processes.
- Standard one-worker installations use one Daphne process for HTTP and
  WebSockets. Deliberately configured multi-worker installations automatically
  retain the previous split high-throughput topology.
- Daphne, Supervisord and Nginx become the container main processes. Redundant
  entrypoint shells are removed and stop/restart signalling is more reliable.

### Measured effect

- RCON3 (HLLV): about 1,099 MiB to 562 MiB under real game traffic, roughly
  49% lower. Later load snapshots were expectedly somewhat higher.
- HLL1 (HLL): about 1,422 MiB to 405 MiB for the comparable core containers,
  roughly 72% lower. Including the unchanged background worker, the totals are
  about 1,572 MiB to 555 MiB, roughly 65% lower.
- Measurements compare the same container scope; short-lived variation from
  RQ jobs and active players remains normal.
- Both canaries retained 18/18 services with no container restart or new
  relevant fatal marker. Seven long-lived core processes run while idle and
  temporarily eight while RQ executes a job.

### Upgrade and rollback safety

- Existing standard installations migrate automatically. Custom Supervisor
  paths and multiple API workers are preserved.
- `FRONTLINE_SUPERVISOR_RUNTIME_MODE=split` and
  `HLL_API_SERVER_MODE=split` restore the compatible former topology without
  a data migration.
- This topology update deletes no data and adds no database migration. Continue
  to back up PostgreSQL, Redis and configuration before updating.
- Upgrade rehearsals passed for HLL and HLLV, split and unified modes, and HLLV
  on ARM. Releases v0.9.0 through v0.9.5 were covered as source versions.
- Newly hosted or reprovisioned instances require Frontline Game Hosting plugin
  v0.17.5 or newer to generate the same guarded runtime settings.
